# Vibe Coding 平台整体架构

版本：v0.3 架构草案  
日期：2026-11-10  
范围：系统组成、模块职责、依赖关系与核心交互

## 1. 架构目标

构建仅支持 TUI、Web 和 Electron 桌面端三种用户入口的 AI 编码平台。云端负责 LLM 推理与任务编排，用户本地负责工具执行和权限控制。

所有入口统一经过本地网关访问云端，本地网关集中管理请求转发、事件分发、执行器和日志。网关采用 Python 实现，作为独立本地服务运行，由客户端启动或复用。

本文只定义整体架构，不规定模块内部实现。接口、协议、数据模型、框架版本、异常处理及测试方案由后续模块设计文档补充。

## 2. 总体架构

```text
用户电脑

               TUI          Web          Electron
                |            |              |
                +------------+--------------+
                            |
                            v
                 本地网关（Python）
                    |       |       |
                    |       |       +----> 本地日志与状态存储
                    |       |
                    |       +------------> 权限与审批
                    |                       |
                    |                       v
                    |                   本地执行器
                    |                       |
                    |                       v
                    |              Shell / 文件 / 搜索 / Git
                    |                       |
                    |                       v
                    |                  用户工作区
                    |
                    | HTTP 提交请求与结果 / SSE 接收事件
                    v
云端

                 API 与连接服务
                         |
                         v
                 Agent 与任务编排
                    |          |
                    v          v
                模型适配层   云端状态存储
                    |
                    v
                LLM 供应商
```

Web、TUI 和 Electron 的业务请求不直接连接云端。本地网关是统一业务出口，云端返回事件也经网关分发到各入口。

本地网关不使用 WebSocket。界面与网关、网关与云端均采用 HTTP 请求和 SSE 事件流：HTTP 提交业务请求、审批及工具结果，SSE 返回模型输出、工具请求和任务状态。

## 3. 架构分层与职责

| 层级 | 模块 | 核心职责 |
| --- | --- | --- |
| 交互层 | TUI、Web、Electron | 接收用户输入，展示任务进度、审批、工具结果和代码变更 |
| 本地协调层 | Python 本地网关 | 统一云端连接、请求转发、事件分发及本地服务生命周期 |
| 本地治理层 | 权限与审批、日志与状态 | 管理执行授权，记录本地业务链路，保存恢复所需状态 |
| 本地执行层 | 执行器、工具模块 | 调度并执行 Shell、文件、搜索与 Git 操作 |
| 云端接入层 | API 与连接服务 | 接收任务，管理客户端连接并传递任务事件与工具请求 |
| 云端应用层 | Agent、任务编排、模型适配 | 管理上下文、调用 LLM、推进任务并处理工具结果 |
| 云端数据层 | 云端状态存储 | 保存会话、任务及其执行记录 |

本地网关与执行器在逻辑上独立，首期可以随同一个本地程序运行。云端各模块同样按职责拆分，不要求从第一天部署为独立微服务。

## 4. 入口与本地网关的关系

- **TUI**：提供终端交互界面，启动或复用本地网关，通过网关完成业务操作。
- **Web**：提供浏览器界面，依赖本机运行的网关，由网关提供本地业务服务。
- **Electron**：提供桌面宿主与系统集成，启动或复用本地网关，界面能力与 Web 共享。

多个入口可以共享同一网关。界面生命周期与网关生命周期分离，关闭单个界面不应直接终止其他入口的任务。

## 5. 云端与本地的职责边界

| 事项 | 云端 | 本地 |
| --- | --- | --- |
| LLM 调用与上下文 | 负责 | 提供必要输入与工具结果 |
| Agent 循环与任务推进 | 负责 | 接收执行请求并反馈状态 |
| 项目文件与运行环境 | 按需获取相关内容 | 保存项目并执行实际操作 |
| 工具执行权限 | 提出工具请求 | 最终决定允许、拒绝或要求审批 |
| 业务请求与事件 | 处理请求、生成事件 | 统一转发、记录并分发给界面 |
| 持久化 | 会话与云端任务状态 | 本地执行状态、策略与日志 |

本地保留项目文件并不意味着内容不会上传。供模型使用的文件片段和工具结果由本地网关按策略发送云端，具体数据规则在相关模块文档中定义。

## 6. 核心交互流程

```text
用户通过任一入口提出需求
            |
            v
本地网关记录请求并转发云端
            |
            v
云端 Agent 调用 LLM
            |
            +---- 返回最终回答 ----> 本地网关 ----> 用户界面
            |
            +---- 生成工具调用
                         |
                         v
                 本地网关接收并记录
                         |
                         v
                 本地权限检查与审批
                         |
                         v
                 执行器调用本地工具
                         |
                         v
                 网关记录并返回结果
                         |
                         v
                 云端 Agent 继续推理
```

任务可经历多轮工具调用。审批、取消、执行状态和模型输出均经本地网关协调，形成可关联的本地业务记录。

## 7. 模块依赖原则

1. 所有交互入口通过统一的本地服务接口访问网关，不各自实现云端业务连接。
2. 网关负责协调，执行器负责调度，工具模块负责具体操作，三者保持明确边界。
3. 本地工具不依赖界面，也不承担 LLM 推理职责。
4. 云端 Agent 核心不依赖界面或具体传输框架，不直接操作用户电脑。
5. 权限控制以本地决策为准，云端请求不能绕过本地策略。
6. 日志与可靠业务状态分开管理，日志不能替代任务和执行状态存储。
7. 云端与本地通过明确的契约协作，独立演进内部实现。
